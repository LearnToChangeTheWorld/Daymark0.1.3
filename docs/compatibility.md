# 客户端兼容与排查

Daymark 按客户端类型选择适配器，**不限定软件必须安装在 C 盘**。安装位置兼容、客户端消息格式兼容、系统运行环境是三个不同问题。

## 当前范围

| 客户端 / 环境 | 读取方式 | 验证情况和限制 |
| --- | --- | --- |
| Windows 微信 4.x x64（Weixin.exe） | 本机数据库只读采集 | 微信 4.1.15.53 已实机验证；其他 4.x 允许尝试，密钥定位、加密和表结构变化可能需更新适配器 |
| Windows 微信 3.x（WeChat.exe，含 x86） | 自动转为 UI Automation 界面读取 | 已接入旧版窗口、会话和消息列表选择器；有合成回归，未完成旧版实机验证；窗口须可读取，首次建立起点，无 7 天历史补读 |
| Windows x64 NTQQ 9.9+ | 随包 NapCatQQ 4.18.38 | 本机 9.9.20.37051 已验证登录与历史；其他构建允许尝试，上游组件兼容性仍有限制 |
| Windows 经典 QQ（如 8.x / 9.7，含 x86） | 独立实验性 UI Automation 适配器 | 不注入 NTQQ 插件；须能从主窗口读到唯一明确的 QQ 号，并识别已打开群的群标识及逐条消息；有合成回归，未完成旧版实机验证；无历史补读 |
| 其他架构 / 未知版本 | 识别后检查能力，失败给出原因 | 不宣称所有版本可用；ARM 原生客户端、封闭控件和变更后的加密格式需要另行适配 |
| Python / Node | 使用完整包内的私有运行环境 | Python 3.10.11 x64、Node 22.23.3；不依赖电脑上 Python 的版本、安装位置或是否安装 |

界面读取不等于后台数据库读取：客户端必须保持登录、群窗口保持可访问，锁屏和窗口关闭可能漏读。无法从界面确定原消息时间时，明确标注“采集时观察到”的时间，不伪造发布时间；不把旧画面当新消息导入。

## 自动查找安装位置

依次使用显式指定路径、运行中客户端的实际程序路径、当前用户和本机的 App Paths / 卸载注册信息、常见系统和用户目录。支持带中文、空格和不同盘符的路径。不全盘搜索，不要求移动或重装客户端。

微信数据库路径根据**当前微信进程打开的数据库句柄**确认，支持聊天记录迁移到其他盘；不会选“最近修改”的账号目录冒充当前账号。初始化密钥校验还会参考 Windows 重定向后的“文档”（含 OneDrive）、微信保存路径设置和用户指定目录。

如果是没有安装记录、尚未运行的特殊便携客户端，可在 PowerShell 中进入 Daymark 文件夹后启动（路径改成自己的实际路径）：

```powershell
$env:STUDENT_INBOX_WECHAT_PATH = 'D:\自己的微信目录\Weixin.exe'
$env:STUDENT_INBOX_QQ_PATH = 'E:\自己的QQ目录\QQ.exe'
.\Start-Daymark.cmd
```

旧版微信的程序名使用 `WeChat.exe`。仅设置需要的那一项；路径填错会明确报错，不会悄悄切到另一个账号或另一份客户端。

微信数据位置特殊且初始化找不到时，可另外设置：

```powershell
$env:WECHAT_DATA_ROOT = 'E:\自己的聊天记录\xwechat_files'
.\Start-Daymark.cmd
```

## 看状态处理问题

- **未找到安装位置**：先打开已安装的客户端再检查；仍失败时可指定程序路径，不等于电脑没有安装。
- **系统拒绝读取账号 / 权限不同**：让客户端和 Daymark 使用同一 Windows 用户、相同权限。优先取消单独对微信启用的管理员运行，不要求日常用管理员启动整个软件。
- **需要初始化本机读取**：适用于微信 4.x。按页面按钮执行一次；初始化会明确重启一次微信。旧版界面方式不执行数据库初始化。
- **表结构尚未适配 / 读取组件不兼容**：保留原消息和采集位置，记录客户端版本反馈，不反复扫码。
- **旧版界面账号或消息控件不可访问**：未开始采集，不显示接入成功。经典 QQ 主窗口需要明确的 QQ 号，群窗口需要明确群标识；私人聊天和消息中的账号文本不会作为本机账号。
- **多个账号同时运行**：保留一个账号再检查，避免混入其他账号的群消息。
- **正在启动**：仅启动请求执行期间显示；失败会结束等待，显示原因，可重新尝试。

`Check-Daymark.cmd` 检查随包 Node、Python 和组件能否加载，另外显示可识别客户端的版本、架构及安装路径。它不会登录、启动或退出聊天客户端，也不能证明每个客户端版本都能读取消息。

## 适配依据

微信 3.x 的界面读取可参考 [wxauto 3.9 源码](https://github.com/cluic/wxauto/blob/main/wxauto/wxauto.py)；微信 4.x 的密钥定位参考已保留 MIT 许可的 [wechat-decrypt](https://github.com/tzwkb/wechat-decrypt)。NTQQ 由 [NapCatQQ](https://github.com/NapNeko/NapCatQQ) 提供接入；界面后端使用 [pywinauto](https://github.com/pywinauto/pywinauto)。本次经典 QQ 适配器为项目自有的实验实现，未引入另一套插件。
