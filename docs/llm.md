# 大模型整理

此功能在本地开发版中提供，默认关闭。打开 **设置 → 大模型整理 → 配置大模型**，普通用户无需编辑配置文件或安装插件。

## 接入 DeepSeek

1. 选择 DeepSeek 模板，填写自己从服务商获取的 API Key。
2. 模型名称已预填，可改为账户当前支持的模型。服务地址默认 `https://api.deepseek.com/v1`。
3. 点击“测试连接”。测试只发送合成测试文字，不发送事项库中的消息。
4. 勾选允许发送待整理文字的说明，再勾选“自动整理启用后新拉取的文字消息”，保存。
5. 如希望下次打开仍可使用，勾选 Windows 加密保存；否则密钥仅本次程序运行有效，重启后重新填写。

调用使用你自己的服务商账户，可能产生费用。Daymark 不附带公共密钥。不要把密钥提交到仓库或发给其他人。

## 其他兼容服务

选择“其他 OpenAI 兼容服务”，填写服务商的 API 地址、模型名称和密钥。使用 Chat Completions 接口，程序自动拼接 `/chat/completions`；可填写以 `/v1` 结尾的地址或完整接口路径。外部服务必须使用 HTTPS，本机服务可使用 HTTP 回环地址。本机免密服务可填写占位密钥 `local`。

服务不支持 `response_format` 时，可在“服务地址与用量设置”关闭 JSON 模式；返回内容仍需通过本地 JSON 结构、原文引用及日期校验。如果服务要求 `max_completion_tokens`，在同处选择新版 OpenAI 输出长度参数。仅提供 Responses 接口的服务不在本次支持范围内。

更换服务地址时必须重新填写对应密钥，避免误将原服务密钥发送给新地址。连接错误、密钥失效、额度不足和响应格式错误会在界面中显示原因；服务返回的原始错误内容不会显示或记录。

## 整理结果

- 新拉取的通知先落盘，再进入后台整理队列，不依赖网页持续打开。同一账号、同一群聊的相邻文字可以作为上下文；账号或群聊之间不混合。
- 一条消息可以拆成多个事项，多条消息可以合并为一个事项；一次请求可返回多个结果。每个事项的正文由 AI 重新提炼为简短句或条目，保留行动、提交位置或方式、适用对象和必要要求，去掉寒暄与重复，目标不超过 300 字。任务详情保留引用原文、消息日期和整理依据，原消息仍可在记录中回查。
- 日期以原消息发布时间和北京时间解释，分别显示截止日期/时刻与事项发生日期/时刻。不把采集日期当作发布时间，不把只有日期的要求补成 23:59。
- 对象不明确、指定个人、自愿参加、日期含糊或缺年份的结果进入待确认。明确变更已有待办的建议也需确认后才更新或归档原待办。
- 你已完成、修改、归档或排除的事项优先；模型结果不会自动覆盖这些操作。关联待办在整理期间发生变化时，需要手动核对。
- 图片、语音和附件只保留文字标记，本次不会读取它们的内容。模型可能遗漏或误解语义，请核对重要事项的原文。

## 历史消息与运行管理

开启自动整理不会直接发送旧消息。历史消息需选择近 1、7 或 30 天，点击“生成预览”，勾选结果后再保留。每次最多 100 条；原发布时间未知、已手动处理或已整理的消息会跳过。历史预览有自己独立的发送确认，暂停自动整理后仍可手动使用。

自动队列保存在本机事项库，重启后恢复。默认每批最多 24 条新消息，可在高级设置调整为 1—48 条；单批正文约 48000 字符，额外上下文有界。每次最多返回 96 个事项，默认输出上限 16384 tokens，可按所选服务支持范围调整为 1024—65536。请求串行执行，起始时间至少间隔 250 毫秒；DeepSeek 官方接口默认关闭深度思考以提高整理速度，可取消快速整理。输出截断或结果校验失败后自动将该批一分为二继续处理，拆分进度保留至重启；单条仍超长时停止重试并提示调整上限，单条仍无法通过原文校验时保留失败原因和原消息。历史预览也支持自动拆分。一般失败最多尝试 3 次；密钥、余额、权限和本地日额度错误直接停止该批重试。失败消息保留，既有文字规则继续提供待办识别；修复配置后可点“重试失败消息”。

每日额度默认提高为 1000 万 tokens，可在高级设置调整，上限 1 亿；已保存的个人额度继续保留。每日 tokens 限额包含自动整理、连接测试和历史预览，按北京时间换日。发起前预留输入字节数加最大输出额度，完成后用服务商返回的实际用量结算；截断响应仍按服务返回的实际用量结算；失败或缺少用量报告时保留估算，可能比实际计费偏高。这是本地用量约束，实际费用以服务商账单为准。

“暂停整理”停止自动处理，并取消正在进行的请求；已保存事项保留。“移除密钥”同时暂停并删除保存的密钥。Windows 加密密钥保存在个人数据目录的事项库中，只能由同一 Windows 账户解密；密钥不返回浏览器，未选择保存时不写入磁盘。完整的消息正文仍按原有方式保存在本机事项库中。

## 开发验证

运行 `node --test test/*.test.mjs`。`tools/llm-ui-check.mjs` 使用独立临时目录、合成消息和本机模拟服务，检查设置、加密保存、预览勾选、自动队列、确认、暂停、重启及窄屏布局，不读取真实账号数据，也不调用外部模型。运行界面检查需要 Playwright 和 Microsoft Edge，可通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块位置。

新增集成集中在 `collector/llm-organizer.mjs`（服务调用、密钥、队列和用量）、`shared/llm-tasks.mjs`（结构校验、日期和结果合并）与 `public/llm.js`（设置和预览界面），没有新增生产运行依赖。
